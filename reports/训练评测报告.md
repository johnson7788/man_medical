## 0. 结论速览

| 口径 | v1(3ep) | v2(2ep) | 参照 | 判定 |
|---|---|---|---|---|
| **总体 Jaccard** | **0.426** | **0.429** | 常量 0.159 / Oracle 0.208 / 规则 0.124 | ✅ 远超所有规则基线 |
| 初诊 Jaccard | 0.279 | **0.301** | 初诊 Oracle 0.254 | ✅ **超过 Oracle** |
| 复诊 Jaccard | **0.509** | 0.501 | 照抄上次方 0.542 | ❌ **不如直接照抄** |
| 关键药 Recall(top100) | **0.613** | 0.609 | Gate 0.45 / Oracle 0.406 | ✅ 通过，且超过 Oracle |
| 证型 micro-F1 | **0.505** | 0.485 | Gate 0.55 | ❌ **未达 Gate** |
| 非法药名率 | 0.04% | **0.02%** | Gate ≤0.5% | ✅ |
| G5 时效漂移 | −5.8% | −10.5% | Gate ≤20% | ✅ |

**一句话**：模型**在初诊上真正超过了「给定真实诊断去检索」的上界**，这证明它在读自由文本而非查表；
但**复诊仍打不过"照抄上次方"**，且**证型识别未达 Gate**。两点都必须正视。

**v1 与 v2 在总体上统计不可分**（配对 bootstrap：差值 −0.003，95% CI [−0.009, +0.003]，p=0.873）。
但构成不同，见 §3。

## 1. 训练

| 项 | v1 | v2 |
|---|---|---|
| 基座 | `XiaomiMiMo/MiMo-V2.6-Distill-Qwen-9B`（9.41B，`Qwen3_5ForConditionalGeneration`） | 同 |
| 微调方式 | **bf16 LoRA**（非 QLoRA；96GB 显存无需 4-bit 量化） | 同 |
| LoRA | r=16, α=32, dropout=0.05, **可训练 43.3M / 9.45B = 0.458%** | 同 |
| epoch | 3（早停 patience=2） | **2**（patience=1） |
| lr / bs / ga | 1e-4 / 8 / 2（有效 batch 16） | 同 |
| 数据 | `train_v2.jsonl` 21,484 / `val_v2.jsonl` 2,675 | 同 |
| 评测样本/epoch | 200 | **400** |
| 每 epoch 评测 padding | **right ❌（bug）** | **left ✅** |
| 耗时 | 3h50m（4029 步，3.22 s/it） | 2h50m（2686 步，3.31 s/it） |
| 选中模型 | epoch 1（md5 与 `checkpoint-1343` 一致） | epoch 2（md5 与 `checkpoint-2686` 一致） |
| 训练吞吐 | 2.57 samples/s（关梯度检查点 + bs8/ga2；bs16 会 OOM 需 95GB） | 同 |

**过拟合是 v1 的核心问题**：eval_loss 0.4952 → 0.5052（epoch1→2），所有指标在 epoch 1 后下降。
v2 改为 2 epoch 后，epoch 2 仍在提升（全部 0.429→0.438、初诊 0.286→0.321），过拟合被解决。

> ⚠️ **v1 的每 epoch 数字（0.401/0.218/0.520）不可信** —— 那次评测用了 right padding。
> 本报告的 v1 数字是**用与 v2 完全相同的解码参数重测**得到的。

## 3. v1 vs v2：总体打平，但构成显著不同

配对 bootstrap（同一样本上比较，消除样本难度差异）：

| 口径 | n | 差值 (v1−v2) | 95% CI | p | 判定 |
|---|---|---|---|---|---|
| 全部 | 2,764 | −0.0032 | [−0.0091, +0.0026] | 0.873 | 不显著 |
| **初诊** | 997 | **−0.0224** | [−0.0340, −0.0120] | 1.000 | **v2 显著更好** |
| **复诊** | 1,767 | **+0.0076** | [+0.0020, +0.0140] | 0.004 | **v1 显著更好** |

**机制解释**：v1 选中的是 epoch 1（训练最少），v2 选中 epoch 2（多训一轮）。
复诊的收益主要来自**照抄上次方**；继续训练会让模型稍微偏离"纯照抄"，转向学到的模式 ——
于是**初诊获益（+0.022）、复诊微损（−0.008）**。总体因复诊占比 63.9% 而相互抵消。

**选型建议**：若产品以初诊（新患者）为主要场景 → **用 v2**；若以复诊管理为主 → v1 略优。
但差异量级很小（初诊 +0.022），在临床价值上都不足以单独支撑决策。

| G1 证型 micro-F1 | 0.505 | 0.485 | 0.55 | ❌ **均未达** |
| G2 处方 Jaccard | 0.426 | 0.429 | 0.22 | ✅ |

| G3 非法药名率 | 0.04% | 0.02% | ≤0.5% | ✅ |
| G3 重复药率 / 空方率 | 0 / 0 | 0 / 0 | ≤0.5% | ✅ |

| G4 人工盲评 | 未做 | 未做 | ≥60% 可用 | ⏳ 待执业中医师 |

## 5. 评测链路修复的 4 个缺陷（都会让结论失真）

| # | 缺陷 | 后果 | 处置 |
|---|---|---|---|
| 1 | `predict.py` 仅在 `--constrained` 时设 left padding，而该项默认关 | 实际用 right padding → **短 prompt 提前 EOS**，17/64 输出全空（全是初诊） | 无条件 left padding + 生成前 assert |
| 2 | 训练脚本评测回调同样是 right padding | v1 的每 epoch Jaccard **绝对值不可信** | 改为 left padding |
| 3 | 约束解码从第 1 个 token 生效 | 把 `【中医诊断】` 整段屏蔽，输出退化为纯药名 | 默认不约束（与训练一致）+ 后置归一化 |
| 4 | `compare_models` 拿模型**复诊**比对方**总体** | 得出"优于照抄"的**错误结论** | 改为同口径比 → 修正为"不如照抄" |

**另有 2 个环境层面的坑**：

- **fla 在 Hopper 上梯度错误**：`Triton >=3.4.0,<3.7.1 on Hopper GPUs produces incorrect results for gated chunk_bwd_dqkwg`。
  torch 2.11 自带 triton 3.6.0 正处于该区间。**已卸载 fla，回到参考实现** ——
  既避免错误梯度，也保证 v1/v2 训练条件一致。
- **PyPI 上的 `flash-linear-attention` 与 `causal-conv1d` 是冒牌包**（前者无 `fla.ops`，后者仅 30KB 无 `.cu`）。

## 6. 评测标准性（本次的硬约束）

1. **一份冻结测试集**：`data/ref_test.jsonl`（2,764 条），模型与全部基线共用。
2. **一套指标代码**：全部经 `evaluate.evaluate()`，无第二套实现。基线复算值与文档完全一致（0.159/0.183/0.208/0.124/0.438）。
3. **参考词表只用训练集**（`ref_train.jsonl`），避免测试集药名进白名单造成轻微泄漏。
4. **选择与报告分离**：模型选择用 val 集，测试集从不参与选择。
5. **初诊/复诊分开报**，并给出加权总体；口径不混用。
6. **bootstrap 置信区间 + 配对检验**：否则"高 0.005"无法判断真假（本次 CI 半宽约 ±0.013）。
7. **解码参数固定且两模型一致**：greedy、batch 32、max_new_tokens 192、left padding。
8. **可复现**：一条命令重跑（见 `model_comparison.md` §5）。

## 7. 未达标项与下一步

| 问题 | 证据 | 建议 |
|---|---|---|
| **证型 F1 未达 Gate**（0.485/0.505 vs 0.55） | G1 表 | 证型是处方的上游，值得单独优化：可用 T1 诊断专用数据（`train_dx_only.jsonl` 50,142 条）做课程学习或先训诊断再联合 |
| **复诊不如照抄**（0.501/0.509 vs 0.542） | 分口径表 | 产品层**直接把"照抄+增删建议"作为复诊基线**，模型只在初诊兜底；或改训练目标为「相对上次方的增删」而非整方生成 |

## 8. 复现

```bash
# 训练机（Linux + NVIDIA GPU）
bash /data/train_v2.sh                    # 训练（2 epoch，约 2h50m）
bash /data/eval_final.sh                  # 生成预测 + 统一对比 + G5
# 单独重跑对比（含 Gate 与配对检验）
python3 src/compare_models.py \
  --model "v1"=data/preds/mimo9b_v1.jsonl --model "v2"=data/preds/mimo9b_v2.jsonl
```

### 演示界面

`src/app_model.py` —— 接入微调模型的 Gradio demo（两个页签）：

| 页签 | 内容 |
|---|---|
| ① 模型推理 | 四诊 → 诊断表格 + 处方 + 剂量填充 + 校验；复诊额外显示**相对上次方的增删** |
| ② 处方校验器 | 手工粘贴处方 → 白名单/十八反/妊娠/剂量/毒性/功效覆盖检查（不需要模型） |

服务器启动与访问（7860 未对公网开放，需隧道）：

```bash
# 服务器
python3 src/app_model.py --base models/MiMo-V2.6-Distill-Qwen-9B --adapter outputs/mimo9b-tcm-lora --port 7860
# 本地
ssh -N -L 7860:127.0.0.1:7860 <user>@<your-server>
# 浏览器打开 http://127.0.0.1:7860
```

实测（Playwright 浏览器端验证）：模型加载 10.4s、单例生成 19–48s；
诊断表格/处方/剂量表/校验结论/免责声明全部渲染；
注入「甘草+甘遂」被正确拦截为 `🔴 block INCOMPAT`。

> ⚠️ 演示端用 batch=1 生成，评测用 batch=32；**批大小会轻微影响数值**（个别样本 argmax 翻转），
> 故演示输出与评测预测可能有个别药味差异，属预期。
