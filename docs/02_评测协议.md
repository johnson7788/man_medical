# 02 · 评测协议

> 本文是本项目**最重要的文档**。医疗 NLP 项目最容易自欺的地方就是评测，
> 而本项目的评测链路曾经真实地错过 4 次（见 §6）。所有数字都必须在本文的约束下解读。

---

## 1. 为什么需要一份"评测协议"

同一个模型，换一套评测口径就能得出相反结论。本项目在开发过程中实际遇到过：

| 事故 | 后果 |
|---|---|
| 训练中途用 right padding 做生成式评测 | v1 的三个 epoch 分数（0.401/0.371/0.362）**全部不可信** |
| 跨口径比较（模型的"复诊"比基线的"总体"） | 得出「优于照抄」的**反向结论**（实际是不如照抄） |
| 同一指标在叙述文档里手工引用 | 覆盖率数字漂移 12 处（89.07% vs 实际 94.44%） |

因此评测必须收敛到：**一个入口、一份数据、一套指标实现**。

## 2. 七条硬约束

### 2.1 一份冻结测试集

`data/ref_test.jsonl`（2,764 条，患者分组切分）。模型与**全部基线**共用同一份。
时间外推用 `data/ref_test_time.jsonl`。

### 2.2 一套指标实现

所有指标只经过 `src/evaluate.py::evaluate`。基线复算值必须与文档一致：

| 基线 | 文档值 | 复算值 | 一致 |
|---|---|---|---|
| 全局常量方 | 0.159 | 0.159 | ✅ |
| 西医诊断检索 | 0.183 | 0.183 | ✅ |
| Oracle 证型+病名 | 0.208 | 0.208 | ✅ |
| 端到端规则 R0 | 0.124 | 0.124 | ✅ |
| 复诊照抄+初诊Oracle X2 | 0.438 | 0.438 | ✅ |

### 2.3 参考统计只用训练集

`--train` 默认指向 `data/ref_train.jsonl`（21,484 条）。
关键药 top100 与药名白名单**只能从训练集统计** —— 若用全量数据统计，
测试集出现过的药会进入白名单，造成轻微泄漏。

### 2.4 选择与报告分离

- **模型选择**：val 集（2,675 条）
- **指标报告**：test 集（2,764 条）

测试集**从不参与**任何超参选择、早停或 checkpoint 挑选。

### 2.5 初诊 / 复诊必须分开报

两者的难度差一个量级：复诊可以照抄上次处方。混在一起报平均数，
会让复诊的大占比（63.9%）掩盖初诊的真实水平。

| 基线 | 全部 | 初诊 | 复诊 |
|---|---|---|---|
| 常量方 | 0.159 | 0.160 | 0.159 |
| Oracle（用真实诊断检索） | 0.208 | **0.254** | 0.182 |
| 复诊照抄 | — | — | **0.542** |

> ⚠️ 注意 **Oracle 的初诊口径是 0.254，不是总体 0.208**。
> 早期版本拿模型的初诊（0.218）去比总体 Oracle（0.208），得出「已超过」的错误结论。

### 2.6 必须给出不确定性

只报点估计时，「v2 比 v1 高 0.005」无法判断真假。本项目给出：

- **bootstrap 95% CI**（1,000 次重采样）—— 判断单个结果与基线的差异
- **配对 bootstrap**（同样本上比较两模型）—— 比各自 CI 是否重叠更灵敏，
  能消除样本难度差异

实测 CI 半宽约 ±0.013。据此判断：

| 对比 | 差值 | 95% CI | p | 结论 |
|---|---|---|---|---|
| v1 − v2（总体） | −0.003 | [−0.009, +0.003] | 0.873 | 不可分 |
| v1 − v2（初诊） | −0.022 | [−0.034, −0.012] | 1.000 | **v2 显著更好** |
| v1 − v2（复诊） | +0.008 | [+0.002, +0.014] | 0.004 | **v1 显著更好** |

### 2.7 解码参数固定且一致

| 参数 | 值 |
|---|---|
| 采样 | greedy（`do_sample=False`） |
| `max_new_tokens` | 192（实测输出 max 158） |
| padding | **left**（见 §6.1） |
| batch | 32 |
| prompt | `medlib.format_input_v2`，与训练完全同口径 |

> ⚠️ **批大小会轻微影响数值**：不同 batch 的 padding 长度不同 → matmul 归约顺序不同 →
> 个别样本 argmax 翻转。所以演示端（batch=1）与评测端（batch=32）的输出可能有个别药味差异，
> 这是预期现象。**比较两个模型时必须用相同 batch**。

## 3. 指标定义

| 维度 | 指标 | 说明 |
|---|---|---|
| 处方（主指标） | **Jaccard** | `|预测∩参考| / |预测∪参考|`，集合级 |
| 处方 | 关键药 Recall(top100) | top100 关键药中被召回的比例 |
| 处方 | micro P/R/F1 | 按药名累加 |
| 处方 | 完全匹配率 | **仅观察，不作 Gate**（诚实口径下多数基线为 0.00%） |
| 诊断 | 病名/证型/治法 micro-F1 | 证型是处方的上游，单独关注 |
| 诊断 | 证型 macro-F1 | 支持度 ≥20 的类别 |
| 结构 | 非法药名率 / 重复药率 / 空方率 | 硬指标 |
| 安全 | 毒性药样本率、寒热同用率 | **预测 vs 参考并列**（只看预测会误判） |

**子集报告**：初诊/复诊、处方重复/非重复、患者多次/单次、常规/异常药味数、
主诉是否现病史前缀。

## 4. Gate 判定

阈值来源 `medlib.GATES`（**单一来源**，`compare_models.py` 与 `evaluate.py` 共用）。

| Gate | 必达 | 目标 | 依据 |
|---|---|---|---|
| G1 证型 micro-F1 | ≥ 0.55 | ≥ 0.65 | 规则基线 0.368 |
| G2 处方 Jaccard | ≥ 0.22 | ≥ 0.30 | **须超过 Oracle 0.208** |
| G2 关键药 Recall | ≥ 0.45 | ≥ 0.55 | > Oracle 0.406 |
| G3 非法药名率 / 重复药率 / 空方率 | ≤ 0.5% | 0% | 结构性硬指标 |
| G4 人工盲评（50 例） | ≥ 60% 可用 | ≥ 75% | 执业中医师 |
| G5 时间外推 Jaccard 相对下降 | ≤ 20% | ≤ 10% | 规则基线实测仅 0.4% |

**分口径目标**：复诊 ≥ 0.45（照抄即 0.542，低于此说明连照抄都不如）；
初诊 ≥ 0.22（须超过初诊 Oracle 0.254 才有说服力，见 §2.5 的口径提醒）。

> ⚠️ **G2 关键药 Recall ≥0.45 高于 Oracle 的 0.406**。这个阈值是刻意设的
> （要求模型超过检索上界），但需注意它在**初诊子集上可能不可达** ——
> 复诊可以靠照抄拿到高分（X2 达 0.601），初诊则困难得多。

## 6. 本项目实际踩过的 4 个评测缺陷

留档以免重犯。**这 4 个都会让结论失真，其中 1 个会让结论反向。**

### 6.1 decoder-only 生成必须用 left padding

`predict.py` 早期版本只在 `--constrained` 为真时设 `padding_side="left"`，
而该选项默认关闭 → 实际用 right padding。

**症状**：`缺诊断段 17/64`，且 **17/17 全是初诊**（短输入）。
输出只有两个空标题行：

```
【中医诊断】
【中药处方】
```

**根因**：right padding 下短 prompt 的 pad 最多，首个 token 从 pad 位置预测 → 提前 EOS。
**决定性证据**：同样本在 batch=1（无 padding）时输出完全正常（药味 15-25 味）。

**修复**：无条件设 left padding + 生成前 `assert tok.padding_side == "left"`。
修复后 `缺诊断段 0/64`。

> 训练脚本的评测回调有同样的问题，导致 v1 的每 epoch 分数不可信。

### 6.2 约束解码不能从第一个 token 生效

`constrained_decode.make_logits_processor` 若从第一个生成 token 就屏蔽非药名 token，
会把 `【中医诊断】` 整段屏蔽掉，输出退化为纯药名列表。

**修复**：默认**不约束**（与训练条件一致）+ 后置药名归一化；
确需解码期硬保证时用两段式（诊断段自由生成，药方段约束）。

### 6.3 跨口径比较会得出反向结论

`compare_models.py` 的结论段早期写成「模型的**复诊** Jaccard vs 基线的**总体** Jaccard」，
于是 0.501 vs 0.438 → 打印「✅ 优于照抄」。
**正确比法**是同口径：0.501 vs 照抄的复诊 0.542 → **❌ 不如照抄**。

### 6.4 叙述文档会静默漂移

同一数字同时活在「脚本生成的报告」和「手工撰写的文档」里，改代码必然忘改文档。
实测抓出 12 处旧值（覆盖率 89.07% → 94.44%）。

**修复**：`src/check_consistency.py` 把叙述文档的关键数字与源报告机械比对，
挂进 `run_stage0.sh` 第 11 步，不通过则退出码非 0。

> 写这个检查器时自己也踩了坑：它报「过时说法仍存在」，而那些正是**修订记录里如实记载的**内容。
> 扫描时必须排除修订记录小节。

## 7. 已知的评测局限

诚实列出，避免过度解读：

| 局限 | 影响 |
|---|---|
| **证型标签存在同义** | 参考中同时有 `肾虚证`(906) 与 `肾虚`(163)、`肝肾亏虚证`(428) 与 `肝肾两虚证`(289)。仅做同义合并即可把证型 F1 从 0.485 提到 **0.538**（距 Gate 仅 0.012）。这 80% 的差距是**标注口径**而非模型能力 |
| **无人工盲评（G4）** | 尚未执行，需执业中医师 |
| **无疗效反馈** | 无法评价处方是否有效，只能评价是否像医生 |
| **Oracle 用真实诊断** | 是检索方案的**上界**，不是可部署方案；用它做基准须说明 |
| **Jaccard 不辨药味重要性** | 君臣佐使被一视同仁；故补充「关键药 Recall」指标 |
| **医师风格未剥离** | 13/16 组风格检验显著（无医生 ID），症状的贡献估计是**上界** |
