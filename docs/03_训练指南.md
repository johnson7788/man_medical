# 03 · 训练指南

---

## 1. 环境要求

| 项 | 要求 |
|---|---|
| Python | ≥ 3.10 |
| GPU | 单卡 ≥ 40GB 显存（实测 H20 96GB） |
| 磁盘 | ≥ 60GB（模型 18.8GB + 数据 + checkpoint） |
| CUDA | 12.8（torch 2.11+cu128 实测通过） |

### 安装（推荐 uv，比 pip 快得多）

```bash
# CUDA 版 torch 必须从官方源装！
# PyPI 上的 nvidia-*-cu13 是 0 字节占位包，会让解析器卡死（实测踩过）
uv pip install --index-url https://download.pytorch.org/whl/cu128 torch
uv pip install transformers>=5.12 peft trl datasets accelerate \
               huggingface_hub modelscope gradio pandas openpyxl
```

> ⚠️ **transformers 版本硬要求**：模型 config 声明 `transformers_version: 5.12.1`，
> 因为 `qwen3_5` 是较新的架构。低于此版本会加载失败或行为异常。

## 2. 准备工作

### 2.1 下载基座

```bash
python3 src/download_model.py --out models/MiMo-V2.6-Distill-Qwen-9B
# 失败可换源：--source hf
```

### 2.2 ★ 必须先跑模型自检

```bash
python3 src/train_sft.py --model models/MiMo-V2.6-Distill-Qwen-9B --inspect
```

**这一步不能省。** 该模型是 **多模态 + 混合注意力** 架构
（`Qwen3_5ForConditionalGeneration`），实测结构：

| 层类型 | 层数 | 模块名 |
|---|---|---|
| 全注意力 | **8** | `q_proj` `k_proj` `v_proj` `o_proj` |
| **线性注意力** | **24** | `in_proj_qkv` `in_proj_z` `in_proj_b` `in_proj_a` `out_proj` |
| MLP | 32 | `gate_proj` `up_proj` `down_proj` |
| 视觉塔 | 27–28 | `qkv` `proj` `linear_fc1/2`（**应排除**） |

> 🔴 **照抄 Qwen3 的 `target_modules` 只会命中 8/32 层注意力，而且不报错** ——
> LoRA 照样能训，只是学了 1/4 的东西。这是本项目最危险的一个坑。

`train_sft.py` 默认用 **auto 自动探测**（排除输出头与视觉塔），无需手填；
`--inspect` 用于人工确认。

期望输出（节选）：

```
[auto target_modules] 选中 12 个: ['down_proj','gate_proj','in_proj_a','in_proj_b',
  'in_proj_qkv','in_proj_z','k_proj','o_proj','out_proj','q_proj','up_proj','v_proj']
[auto target_modules] 排除 1 个: ['lm_head']
    in_proj_qkv              ×24
    q_proj                   ×8
```

### 2.3 数据校验（无需 GPU）

```bash
python3 src/train_sft.py --model models/MiMo-V2.6-Distill-Qwen-9B --dry-run
```

会检查：train/val 与 `ref_*` 条数对齐、val 是否同时含初诊与复诊、
序列长度是否超出 `max_length`、步数估算、依赖是否齐备。

## 3. 训练

### 3.1 推荐配置（实测）

```bash
python3 src/train_sft.py \
  --model models/MiMo-V2.6-Distill-Qwen-9B \
  --quant none \
  --train-file data/train_v2.jsonl \
  --val-file   data/val_v2.jsonl \
  --output-dir outputs/mimo9b-tcm-lora \
  --epochs 2 --lr 1e-4 --bs 8 --ga 2 --no-grad-ckpt
```

| 超参 | 值 | 说明 |
|---|---|---|
| `--quant` | `none` | **bf16 LoRA**。96GB 显存下不需要 4-bit QLoRA，更快且无精度损失 |
| `--epochs` | **2** | 实测 3 epoch 会过拟合（见 §4） |
| `--lr` | 1e-4 | 2.1 万条 / 有效 batch 16 |
| `--bs` / `--ga` | 8 / 2 | 有效 batch 16。**bs=16 会 OOM**（需 95GB） |
| `--no-grad-ckpt` | — | 关梯度检查点。**吞吐 0.466 → 2.572 samples/s（5.5×）** |
| `--eval-samples` | 400 | 每 epoch 生成式评测样本数；200 时初诊仅 79 条，噪声大 |

**实测性能**（单卡 H20 96GB）：

| 项 | 值 |
|---|---|
| 可训练参数 | 43.3M / 9.45B = **0.458%** |
| 训练吞吐 | 2.572 samples/s |
| 单步耗时 | ~3.3 s（有效 batch 16） |
| 2 epoch 总耗时 | **2h50m**（2,686 步） |
| 峰值显存 | ~78GB |

### 3.2 冒烟测试（强烈建议先跑）

```bash
python3 src/train_sft.py --model models/MiMo-V2.6-Distill-Qwen-9B --quant none \
  --max-steps 20 --eval-strategy no --bs 2 --ga 1 \
  --output-dir outputs/smoke
```

20 步就能验证：模型加载、LoRA 生效、数据格式、保存路径。约 90 秒。

## 4. ⚠️ 过拟合是真实存在的

v1（3 epoch）的每 epoch 评测：

| epoch | 全部 J | 初诊 J | 复诊 J | 证型F1 | 非法率 |
|---|---|---|---|---|---|
| **1** | **0.401** | 0.218 | **0.520** | **0.499** | 1.50% |
| 2 | 0.371 | 0.147 | 0.518 | 0.466 | 0.50% |
| 3 | 0.362 | 0.198 | 0.469 | 0.477 | 0.50% |

`eval_loss`：0.4952 → 0.5052（epoch1→2），**确认过拟合**。

v2（2 epoch）：

| epoch | 全部 J | 初诊 J | 复诊 J | 证型F1 | 非法率 |
|---|---|---|---|---|---|
| 1 | 0.429 | 0.286 | 0.517 | 0.541 | 0.50% |
| **2** | **0.438** | **0.321** | 0.510 | **0.547** | 0.00% |

**2 epoch 是合适的。** 训练脚本配 `load_best_model_at_end=True`
（`metric_for_best_model=eval_subset_jaccard`，即初诊/复诊的**未加权**平均），
会正确回退到最优 checkpoint（已用 md5 校验）。

> 选未加权平均而非样本加权总体，是因为它不会被占比 63.9% 的复诊掩盖初诊的退化。

## 5. 训练脚本相对参考实现改了 7 处

如果你手上有一份常见的 SFT 参考脚本，注意这些必要改动：

| # | 改动 | 理由 |
|---|---|---|
| 1 | lr 2e-4 → **1e-4** | 2.1 万条 / 3 epoch，30B 上 2e-4 易过拟合 |
| 2 | **增加 val 集与早停** | 原脚本只有 train，无法发现过拟合 |
| 3 | max_length 2048 → **1024** | 序列实际很短（p99=360，max=531） |
| 4 | **清理注释掉的 `get_peft_model` 死代码** | SFTTrainer 传 `peft_config` 已生效，重复包装会出问题 |
| 5 | 显式 **packing=False** | 样本短且独立，packing 会跨样本污染 |
| 6 | **初诊/复诊分开评测** | 两者难度差一个量级 |
| 7 | **接入约束校验器监控** | 生成后过一遍 `validate_rx`，把非法药名率作为监控项 |

## 6. 训练期的坑（都实际踩过）

### 6.1 `print_trainable_parameters()` 的调用位置

它是 **PEFT** 的方法，只有当 LoRA 套上之后才存在。
SFTTrainer 内部的 `peft_config` 会在构造 trainer 时应用，
所以必须在 `SFTTrainer(...)` **之后**调用。

**已加防静默失效的硬校验**：

```python
n_train = sum(p.numel() for p in trainer.model.parameters() if p.requires_grad)
if n_train == 0:
    raise RuntimeError("LoRA 可训练参数为 0 —— target_modules 未命中任何层")
if n_train / n_total > 0.5:
    raise RuntimeError("可训练参数占比过高 —— LoRA 未生效（等于全参微调）")
```

### 6.2 `warmup_ratio` 在 transformers 5.x 被移除

报错：`SFTConfig.__init__() got an unexpected keyword argument 'warmup_ratio'`。
替代是 `warmup_steps`。脚本里保留 `warmup_ratio` 作为**本模块配置**，
在 `train()` 内按实际总步数换算（总步数 8,055 → warmup_steps 241）。

### 6.3 优化器要按量化方式选

`paged_adamw_32bit` 需要 bitsandbytes（QLoRA 的配套）。
**bf16 LoRA 用 `adamw_torch` 即可**，不必引入该依赖。
脚本已按 `--quant` 自动选择。

### 6.4 评测回调必须用 left padding

否则每 epoch 的 Jaccard 全部不可信。详见
[`02_评测协议.md`](02_评测协议.md) §6.1。

### 6.5 长任务日志必须无缓冲

带 `| grep` 的管道会引入 4KB 块缓冲，7 小时的训练**全程看不到进度**。
用 `stdbuf -oL` 或 `python -u`。

### 6.6 `pgrep -f <pattern>` 会匹配到自己

`pkill -f "uv pip install"` 的命令行本身含该字符串 → **杀掉自己的会话**
（表现为"命令没有任何输出、exit 1"）。
用方括号技巧：`pkill -f "uv pip insta[l]l"`，
或把清理与启动放在**不同的 ssh 会话**里。

### 6.7 不要用 flash-linear-attention（当前环境）

该模型有 24 层线性注意力，fla 能显著加速，但：

```
RuntimeError: Triton >= 3.4.0 and < 3.7.1 on Hopper GPUs produces
incorrect results for gated chunk_bwd_dqkwg
```

torch 2.11 自带 triton 3.6.0 正处于该区间 → **梯度错误**。
要么升级 triton ≥ 3.7.1，要么用参考实现（本项目选择后者，以保证正确性与可比性）。

> 另注：PyPI 上的 `flash-linear-attention` 与 `causal-conv1d` 是**冒牌包**
> （前者无 `fla.ops`，后者仅 30KB 无 `.cu` 文件）。真货在 GitHub。
