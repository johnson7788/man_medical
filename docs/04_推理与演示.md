## 1. 批量推理（`src/predict.py`）

在冻结测试集上生成预测，产出与 `evaluate.py` 对齐的 `{"rid","output"}` 文件。

```bash
python3 src/predict.py \
  --model   models/MiMo-V2.6-Distill-Qwen-9B \
  --adapter outputs/mimo9b-tcm-lora \
  --ref     data/ref_test.jsonl \
  --out     data/preds/mimo9b.jsonl
```

| 参数 | 说明 |
|---|---|
| `--adapter` | LoRA 路径；不传则用基座 |
| `--subset {all,first,fu}` | 只跑初诊/复诊 |
| `--limit N` | 只取前 N 条（快速抽样） |
| `--sample N` | **分层随机抽样** N 条（按初诊/复诊比例，固定种子可复现） |
| `--batch` | 默认 4；实测 32 已足够快（0.5 s/条） |
| `--max-new-tokens` | 默认 320；实测输出 max 158，192 足够 |
| `--constrained` | 启用 462 白名单约束解码（**默认关**，见 §3） |
| `--normalize` | 药名后置归一化（默认开） |
| `--v1-input` | 用不含既往处方的输入（对照实验） |

### 关键实现点

1. **无条件 left padding**（并 `assert`）
   decoder-only + right padding 会让短 prompt 提前 EOS。
   实测：17/64 条输出只剩两个空标题行，且全是短输入的初诊。

2. **输入用 `format_input_v2`**，与训练完全同口径。口径不一致会让评测失真。

3. **药名后置归一化**：复用 `build_external_data` 的炮制/产地/后缀剥离规则，
   把模型输出的写法变体映射回 462 白名单，并报告越界率。

### 实测性能

| 项 | 值 |
|---|---|
| 吞吐 | **0.5 s/条**（batch 32，H20） |
| 全测试集 2,764 条 | 约 23 分钟 |
| 模型加载 | 约 10 秒（权重在 page cache 时） |

## 3. 约束解码（`src/constrained_decode.py`）

三层约束，各用对的手段：

| 约束 | 手段 | 为什么 |
|---|---|---|
| 药名 ∈ 462 白名单 | **trie 逐 token 引导** + vLLM guided_json/regex | 中文药名常被切成多 token（`炙淫羊藿` 2–3 个），简单"允许 token 集合"会放出半个药名 |
| 十八反/十九畏 | 「生成→校验→剔除违规药→重生成」有界修复 | 这是**集合级**关系，与生成顺序无关，token 级无法预判 |
| 功效覆盖治法 | **不做硬约束**，仅作提示 | 实测判别力仅 **7.9%**，硬约束会误伤合理处方 |

### ⚠️ 默认关闭的原因

若从**第一个生成 token** 就施加白名单约束，会把 `【中医诊断】` 整段屏蔽掉，
输出退化为纯药名列表（实测踩过）。

**默认策略：不约束生成 + 后置归一化。** 这与训练条件一致，
且 `predict.py` 实测归一化后越界率仅 **0.01–0.03%**。

确需解码期硬保证时，用两段式（`constrained_second_pass`）：
诊断段自由生成 → 在 `【中药处方】` 之后对药方段施加约束。

### 离线自检（无需 torch/vLLM）

```bash
python3 src/constrained_decode.py --selftest
```

验证：462 味全部沿 trie 可达、3,000 次受约束生成零越界、
guided_regex 462/462 命中且拒绝白名单外药名、十八反修复循环生效。

## 4. 安全后置链路

### 4.1 处方校验器（`src/validate_rx.py`）

```python
from validate_rx import Validator
v = Validator()
v.validate_prescription(rx, tcm_dx, patient=None) -> dict
# → {verdict, coverage, confidence, findings, handling_alerts}
```

| 表现 | 数值 |
|---|---|
| 真实处方误报率（warn 及以上） | **5.62%** |
| 安全类检出（幻觉药/十八反/妊娠/剂量上限） | **100.0%** |
| 缺失检测（删掉支撑治法的药） | **100.0%** |
| 治法判别（治法替换为无关） | ⚠️ **仅 7.9%** |

> 🔴 **它做的是缺失检测**（方中有没有药支撑该治法），**不是治法判别**（该治法选得对不对）。
> **不可用作模型"治法"输出的奖励信号。**
> 原因：15 味药横跨多个功效类别，不相交的治法也能被"碰巧覆盖"。
> 实测反例：模型诊断"阴虚证·滋阴"却开出柴胡类方、无滋阴药，
> 校验器仍报 `verdict=ok, coverage=1.0`。

**设计纪律**：

| 决策 | 依据 |
|---|---|
| block 只用于安全性 | 覆盖率硬拦会误杀医生处方（约 3% 是真实的标签/方药不一致） |
| 不做朴素寒热矛盾检查 | 真实处方寒热并用占 **17.3%**（交泰丸、乌梅丸即如此） |
| 毒性药提示不计入 verdict | 47% 真实处方含此类药材，计为 warn 会让 warn 级别失效 |
| 阈值全部外置 | 中医师改 `data/external/validator_config.json` 即可 |

### 4.2 剂量填充层（`src/dose_filler.py`）

**模型不生成剂量**（原始数据 99.7% 的剂量是常量 `1.000`，编造 = 临床风险）。

```python
from dose_filler import DoseFiller
df = DoseFiller()
filled = df.fill(["北柴胡", "黑顺片", "茯苓"])
print(df.render(filled))
```

| 策略 | 说明 |
|---|---|
| 有毒/需特殊处理药材 | 取区间**下限**（宁少勿多） |
| 常规药材 | 取区间中位 |
| 恒返回 | 区间 + 原文说明（含炮制差异，机器无法替医生决定） |
| 字典缺失 | 显式标注「待人工填写」，不留空、不猜 |
| 可填充用量占比 | **94.44%** |

## 5. 演示界面（`src/app_model.py`）

```bash
python3 src/app_model.py \
  --base models/MiMo-V2.6-Distill-Qwen-9B \
  --adapter outputs/mimo9b-tcm-lora \
  --host 0.0.0.0 --port 7860
```

### 两个页签

**① 模型推理**（四诊 → 诊断 + 处方）

- 左侧表单 + 三个真实病例可一键载入
- 右侧输出：诊断表格、处方、剂量表、校验结论
- **复诊额外显示「相对上次处方的调整」**：沿用/新增/去掉各几味 + 与上次方重合度

> 为什么复诊要显示增删：本数据 63.9% 是复诊，其最强基线就是"照抄上次方"。
> 只给一张新方，无法判断模型是照抄还是调整。

**② 处方校验器**（不需要模型，秒出）

手工粘贴处方 → 白名单 / 十八反 / 妊娠禁忌 / 剂量上限 / 毒性药 / 功效覆盖检查。

### 其他参数

| 参数 | 说明 |
|---|---|
| `--no-model` | 只启动校验器页签（无 GPU 也能跑） |
| `--smoke` | 只构建界面并退出（CI 用，不启动服务） |
| `--share` | Gradio 公网分享链接 |
| `--auth user:pass` | **开启基础认证**。公网暴露时强烈建议开启，否则任何人都能白用你的 GPU |

### 性能预期

- 模型加载：约 10 秒
- 单例生成：**19–48 秒**（batch=1，真实推理，非缓存）

> ⚠️ 演示端 batch=1、评测端 batch=32，**批大小会轻微影响数值**
> （padding 长度不同 → 归约顺序不同 → 个别样本 argmax 翻转）。
> 所以演示输出与评测预测可能有个别药味差异，属预期现象。
