## 2. 已实施的脱敏：机构名归一化

### 问题

1,716 条记录（占 2.56%）含医院名，计 234 个不同名称，且高度集中：

| 医院名 | 出现次数 |
|---|---|
| 在区医院 | 552 |
| 在北大医院 | 171 |
| 北大医院 | 134 |
| 在京顺医院 | 128 |
| 于顺义区医院 | 120 |
| 于友谊医院 | 119 |
| 就诊顺义区医院 | 110 |
| 就诊西苑医院 | 101 |
| 人民医院 | 86 |
| 安贞医院 | 84 |

**这些名称的组合足以推断出数据来源机构**，而院方未必同意被公开识别。

### 处理

`src/sanitize_for_release.py` 把 `<中文名> + 医院|卫生院|诊所|门诊部` 统一替换为 **「外院」**：

```
就诊西苑医院          → 就诊外院
北大医院后尿道断裂术后  → 外院后尿道断裂术后
人民医院口服前列舒通胶囊 → 外院口服前列舒通胶囊
```

选「外院」是因为它同时适配所有出现的句式，且保留临床语义（"外院做过什么手术/检查"）。

| 项 | 结果 |
|---|---|
| 命中记录 | 3,751 条（覆盖全部 15 个 jsonl，含 ChatML 格式） |
| 替换处数 | 3,959 处 |
| 脱敏后残留机构名 | **0** |
| 幂等性自检 | **0** 处残留（可重复执行） |
| 报告 | `reports/sanitize_report.md` |

> ⚠️ 实现时踩过一个坑：早期版本只处理了顶层 `cc`/`hpi` 字段，
> 而 **ChatML 格式的训练文件**把文本放在 `messages[i]["content"]` 里 ——
> 导致 `train*.jsonl` / `val*.jsonl` / `test*.jsonl` **漏脱敏**。
> 已修复并覆盖两种数据形态。

### 按决定未做：日期平移

就诊日期保留原值（2023-01-01 ~ 2026-09-08）。
理由：需要完整时间信息以支持时效性评估（G5）。**代价**：若有人持有院方原始记录，
理论上可做日期+科室的交叉比对。若你认为这个风险不可接受，可以改做平移：

```python
# 全部日期加固定偏移，保留间隔与先后顺序，破坏绝对日期对应
from datetime import datetime, timedelta
SHIFT = timedelta(days=137)   # 任选，需保密
```

## 3. 脱敏对模型与指标的影响（实测）

因为脱敏改变了自由文本，而**模型输入包含自由文本**，必须量化影响。

### 基线：完全无影响

所有规则基线只用结构化字段（西医诊断/性别/年龄/证型），
脱敏前后 **7/7 项差值 +0.0000**。

### 模型：影响可忽略

测试集 2,764 条中，自由文本发生变化的只有 **26 条（0.94%）**。
用**同一个模型**分别跑旧文本与脱敏后文本：

| 项 | 结果 |
|---|---|
| 旧文本平均 Jaccard | 0.3715 |
| 脱敏后平均 Jaccard | 0.3688 |
| 差值 | **−0.0027** |
| 单条输出发生变化的 | 8 / 26 |
| **折合到全测试集的影响** | **≈ −0.00003** |

**结论：已发布的模型权重与报告指标继续有效，无需重训。**
（CI 半宽 ±0.013，该影响小两个数量级。）

> 复现该实验：`src/sanitize_for_release.py --check` 列出受影响记录，
> 用旧/新文本各跑一次 `predict.py` 对比。

## 4. ⚠️ 未解决的风险

按严重程度排序。**这些是"知道但没解决"，不是"已解决"。**

### 4.1 无伦理审查（IRB）与患者知情同意 —— 高

本项目派生自真实临床病历。虽然做了 ID 哈希与机构名归一化，
**但没有经过伦理审查委员会审批，也没有患者知情同意**。

- 若你要**再分发**数据或模型：请先确认所在机构/地区的合规要求
- 若你要**商用**：`LICENSE-DATA` 已明确禁止（CC BY-NC 4.0）
- 若院方主张权利：应配合下架

### 4.2 罕见组合可能重识别 —— 中

男科 + 特定罕见诊断 + 精确就诊日期 + 年龄，组合起来理论上可能指向个体。
25,103 名患者的规模降低了风险，但**并非为零**。
如需进一步降低，建议平移日期 + 年龄分箱（本项目未做）。

### 4.3 舌象/脉象字段缺失 —— 数据质量（非隐私）

舌 0.53% / 脉 0.74%。这不影响隐私，但意味着**辨证的输入前提不完整**，
模型存在原理性上限（实测 12.3% 的相同输入下医生给出不同证型）。

### 4.4 医师个人风格未剥离 —— 方法（非隐私）

无医生 ID，13/16 组风格检验显著。这污染症状的贡献估计（`+0.040` 是**上界**）。

## 5. ⚠️ 许可冲突与处理

### 冲突

你为数据选择了 **CC BY-NC 4.0**（禁止商用）。但外部知识库「本草典开放数据 v1」
采用 **CC BY-SA 4.0**，其 ShareAlike 条款要求**派生作品以相同许可分发**，
**不允许附加 NC 限制** —— 两者**不兼容**。

而 `data/external/herb_dictionary.jsonl` 等文件确实派生自本草典。

### 处理：分开存放、分别许可

| 范围 | 许可 | 位置 |
|---|---|---|
| `src/` 源代码 | Apache-2.0 | `LICENSE` |
| `data/` 自行派生数据（患者数据） | CC BY-NC 4.0 | `LICENSE-DATA` |
| `data/external/` 外部知识库派生文件 | 依各源，本草典部分为 **CC BY-SA 4.0** | `data/external/LICENSE` |

这是标准做法：**只要 CC BY-SA 内容能被清晰分离，就可以各自许可。**

### 你需要知道的两件事

1. **若有人要把两者合并再分发**，整体只能采用 CC BY-SA 4.0（NC 会被 SA 覆盖）。
2. **`herb_dictionary.jsonl` 等文件必须署名「本草典开放数据 v1」并附许可链接**，
   并以其派生作品继续使用 CC BY-SA 4.0。已在 `data/external/LICENSE` 写明。

另有两个来源的许可较弱，需注意：

| 来源 | 许可 | 风险 |
|---|---|---|
| SymMap v2.0 | 声明限学术研究、不得商用；**仅提供 HTTP** | 已用于字典合并 |
| TCM-Prescription-Recommendation | **原仓库未附许可文件** | 仅用于内部统计，未进发布产物必要路径 |
| PresRecST | 学术研究使用 | 用于可行性验证 |
